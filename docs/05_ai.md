# 05. Inteligência Artificial

**Status:** Draft | **Última atualização:** 2026-08-03

## 5.1 Onde Utilizar IA

Distinguimos dois tipos de "IA" no projeto:

1. **IA de Runtime (in-game)**: lógica leve executada no dispositivo — comportamento de inimigos, dificuldade dinâmica, geração procedural. **Não usa LLMs** (custo/latência incompatíveis com mobile real-time); usa heurísticas, FSMs, curvas e Utility AI.
2. **IA Generativa (produção/ferramentas)**: usada por agentes LLM durante o desenvolvimento para gerar código, dados de balanceamento, variações de conteúdo (textos de UI, nomes de itens), e para gerar assets via pipelines externos (ver `09_art.md`). **Não roda no cliente do jogador em tempo real.**

## 5.2 IA para Geração de Conteúdo

- **Layout de Rifts**: algoritmo procedural (não-LLM) que distribui Rifts nas superfícies classificadas (`03_ar_system.md` §3.3), respeitando distância mínima entre Rifts, ângulo de visão da câmera inicial e distribuição balanceada entre paredes/chão/teto/móveis.
- **Composição de ondas**: seleção procedural de `FragmentDefinitionSO` a partir de um "orçamento" (Wave Budget) que cresce por onda — similar a orçamento de spawn de horde-shooters.
- **Geração de variações de texto** (tooltips, nomes de desafios diários, flavor text de itens): pipeline offline usando LLM (Claude via API), com revisão humana antes de entrar em produção — nunca geração em runtime no cliente.

## 5.3 IA para Balanceamento

- Dados de telemetria (ver `12_analytics.md`) agregados em dashboard; processo periódico (offline, não em tempo real) usa análise estatística para sugerir ajustes em `DifficultyCurveSO` e `WaveDefinitionSO`.
- Agentes de IA (LLM) podem ser usados no processo de design para analisar relatórios de analytics e propor ajustes de balanceamento como PRs de dados (arquivos SO serializados/JSON), sempre revisados por um humano antes de merge.
- **Remote Config**: valores de balanceamento carregados de backend (`11_backend.md`) permitem ajuste sem nova build — não é "IA" em si, mas é o mecanismo de entrega dos ajustes sugeridos.

## 5.4 IA para Dificuldade (Dynamic Difficulty Adjustment — DDA)

### Sinais monitorados por sessão (`DifficultyDirector`)
- `HitRate` (acertos / lançamentos) — janela deslizante das últimas 10 ações.
- `AvgReactionTime` (tempo entre spawn de ameaça relevante e resposta do jogador).
- `CoreDamageRate` (dano ao Core por minuto).
- `PowerupUsageEfficiency`.

### Algoritmo (heurístico, não ML)
```
skill_score = w1*HitRate + w2*(1/AvgReactionTime) + w3*(1 - CoreDamageRate_normalizado) + w4*PowerupUsageEfficiency
difficulty_delta = clamp((skill_score - target_skill_score) * sensitivity, -0.15, +0.15)
next_wave_params = base_curve(wave_index) * (1 + difficulty_delta_acumulado)
```
- `sensitivity` e `target_skill_score` são parâmetros tunáveis via `DifficultyCurveSO`, ajustáveis remotamente.
- Ajuste aplicado apenas no início de cada onda (nunca mid-wave) para não parecer "trapaça".
- Modo Endless usa a mesma lógica mas sem teto de dificuldade (escalonamento geométrico após certo ponto).

## 5.5 IA para Comportamento dos Inimigos (Fragments e Bosses)

- **Fragments comuns**: Utility AI simples — score de decisão entre `Seek Core`, `Flank via superfície lateral`, `Retreat momentâneo` baseado em distância, HP restante e presença de Orbes em voo próximos (evasão básica).
- **Fragments elite**: adicionam padrão de movimento evasivo mais assertivo e habilidade de "quebrar" combos do jogador (interpõem-se para forçar erro de mira).
- **Bosses (Rift Maior)**: Máquina de Estados por fase (`04_architecture.md` §4.10) com Utility AI para escolha de ataque dentro de cada fase, ponderando: weak points já destruídos, posição do jogador (ângulo da câmera), cooldowns disponíveis.
- Pathfinding sobre geometria real: grid de navegação leve gerado a partir dos planos AR detectados + depth raycasts pontuais (não NavMesh completo — custo alto de bake em ambiente dinâmico); usar `Simple Flow Field` recalculado a cada 1–2s.

## 5.6 IA para Geração Procedural

- **Seed determinística por sessão**: permite o Modo Desafio Diário (mesma seed para todos os jogadores no dia).
- **Geração de padrão de Rifts**: distribuição via Poisson-disc sampling sobre as superfícies classificadas, para evitar clusters não naturais.
- **Geração de composição de bioma visual**: seleção procedural de `BiomeThemeSO` baseada em progressão do jogador + rotação sazonal, não em análise do ambiente real (evita viés problemático de "julgar" o cômodo do usuário).

## 5.7 Uso de Agentes de IA no Processo de Desenvolvimento

Diretrizes para quando um agente LLM for usado para gerar código/assets deste projeto:

- Sempre gerar código C# aderente aos padrões de `04_architecture.md` (DI via VContainer, eventos via SO, sem Singletons estáticos).
- Sempre referenciar o ID da tarefa do `15_backlog.md` no commit/PR.
- Nunca gerar lógica de gameplay crítica (economia, anti-cheat) sem revisão humana explícita — ver `17_security.md`.
- Assets gerados por IA (arte, áudio) devem passar por revisão de direção de arte (`09_art.md`) antes de entrar em build.
